# Sana — React frontend

React + TypeScript интерфейс для backend Sana. Исходники тиммейта импортированы из
`damirzhumangali/KassaCV_backend`, ветка `feat/react-frontend`, ревизия `9a0af88`.
Основная рабочая версия теперь находится в `frontend/` репозитория Sana.

## Запуск

Нужен Node.js 24+. Сначала настройте и запустите backend из корня Sana.
Во втором терминале перейдите в эту папку:

```powershell
cd frontend
npm.cmd ci
# Создать .env.local один раз, после настройки корневого .env:
npm.cmd run configure
npm.cmd run dev
```

Откройте http://127.0.0.1:3000. Скрипт `configure` читает `../.env` и создаёт
игнорируемый Git файл `.env.local`, копируя ключ и лимит размера без вывода секрета.
Существующий файл не перезаписывается. Для другого адреса backend:

```powershell
npm.cmd run configure -- ..\.env http://127.0.0.1:8001
```

Можно создать `.env.local` по `.env.example` вручную:
`BACKEND_URL` — адрес FastAPI; `API_KEY` — тот же ключ, что в backend;
`VITE_MAX_UPLOAD_MB` — подсказка лимита, совпадающая с `MAX_UPLOAD_MB`.
После изменения настроек перезапустите Vite.

## Соединение

React отправляет относительные запросы:
- `POST /api/v1/analyze`: один `.mov` в multipart-поле `file`;
- `GET /api/v1/jobs/{job_id}`: `processing`, `done`, `failed`;
- `GET /health`: проверка HTTP-сервера, не готовности модели.

Локальный Vite-прокси добавляет `X-API-Key` на стороне Node. Ключ не находится
в React, localStorage или сборке. Не создавайте `VITE_API_KEY`: переменные
`VITE_*` доступны браузеру. CORS для этой схемы не требуется:
[server.proxy Vite](https://vite.dev/config/server-options.html#server-proxy).

Это локальная схема: Vite слушает только `127.0.0.1` и не авторизует пользователей.
Публичный запуск, HTTPS и серверную авторизацию подготовим отдельно.
`npm run build` создаёт статический `dist` без серверного прокси;
публичный сервер должен сам маршрутизировать `/api` и `/health`.
`npm run preview` предназначен для локальной проверки сборки.

## Поведение и проверки

Демонстрационные результаты не выдаются вместо анализа. Сначала экран пустой.
После загрузки показываются настоящий UUID и статус задачи. Опрос выполняется
последовательно примерно раз в 1,5 секунды; при уходе со страницы запросы прекращаются.
Ошибки `{code,message}` отображаются без успешного вердикта.
Без настроенного AI задача станет `failed / JOB_TIMEOUT` после общего срока.

Поддерживаются `.mov` и `.MOV`, по умолчанию до 100 МиБ. Backend проверяет лимиты
независимо от браузера. Предпросмотр зависит от кодека; его ошибка не мешает отправке.
История и кадры хранятся в памяти вкладки, без записи в localStorage.
Примеры из `src/data` не подключены к рабочему экрану. Отсутствующие confidence и
источники не заменяются выдуманными значениями. Нормативный источник в текущем
контракте API находится в `description`.

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

Тесты API-клиента проверяют multipart, оба вердикта, структурированные ошибки,
перегрузку, авторизацию, некорректные ответы и отмену запроса.
Подробная инструкция команды: [../docs/frontend-integration.md](../docs/frontend-integration.md).
