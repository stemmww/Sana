# React frontend и совместный запуск

Backend и frontend находятся в одном репозитории Sana:
`app/` — FastAPI, `frontend/` — React + TypeScript.
Для работы достаточно одного клонирования. Корневой `main` должен содержать
эту папку после объединения ветки `feat/frontend-integration`.

Исходники интерфейса импортированы из
[ветки тиммейта](https://github.com/damirzhumangali/KassaCV_backend/tree/feat/react-frontend),
ревизия `9a0af88`, с исправлениями подключения к нашему API.
В исходном репозитории frontend-ветка удаляет backend-файлы своего родительского
`main`. В Sana перенесены только frontend-исходники в отдельную папку, без
вложенного `.git`, зависимостей, сборки или секретов.
Старая локальная папка `Sana-frontend` сохранена; для дальнейшей работы используйте
`Sana/frontend`.

## Как идут запросы

Браузер обращается к http://127.0.0.1:3000. Vite передаёт `/api` и `/health`
в FastAPI, по умолчанию на http://127.0.0.1:8000.
Заголовок `X-API-Key` добавляет Node-процесс прокси; браузер не получает ключ
из `.env.local`. Адреса запросов React относительные, CORS в FastAPI для
этой конфигурации не нужен: [server.proxy Vite](https://vite.dev/config/server-options.html#server-proxy).

Это локальная схема разработки. Vite слушает `127.0.0.1` и не авторизует
пользователей. Для публичного запуска отдельно нужны HTTPS, доступ пользователей
и серверный прокси. Статический `dist` не содержит прокси: публичному серверу
потребуется собственная маршрутизация `/api` и `/health`.
При прямых запросах между разными origin потребуется отдельная
[настройка CORS](https://fastapi.tiangolo.com/tutorial/cors/).

## Первый запуск у тиммейта

Нужны Git, Python 3.11+ и Node.js 24+. Текущий backend проверен на Python 3.14;
после интеграции AI согласуйте Python с зависимостями моделей.
Команды ниже для Windows PowerShell, после публикации изменений в `main`.

```powershell
git clone https://github.com/stemmww/Sana.git
cd Sana
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

Вставьте сгенерированный ключ в `API_KEY` корневого `.env` вместо заглушки.
Каждый тиммейт при локальном запуске может использовать собственный ключ.
Файлы `.env` и `frontend/.env.local` не передаются через Git.

Первый терминал, из корня Sana:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Если backend уже запущен на этом порту, используйте работающий процесс.
Во втором терминале, также из корня Sana:

```powershell
cd frontend
npm.cmd ci
# Только если .env.local ещё нет:
npm.cmd run configure
npm.cmd run dev
```

Откройте **http://127.0.0.1:3000**.
`configure` читает `../.env`, копирует ключ и лимит размера без вывода секрета
и отказывается перезаписывать существующий `.env.local`.
Не используйте имя `VITE_API_KEY`: переменные с префиксом `VITE_` попадают
в браузерную сборку.

Для другого адреса backend при первом создании:

```powershell
npm.cmd run configure -- ..\.env http://127.0.0.1:8001
```

После изменения ключа, адреса или лимита обновите `frontend/.env.local`
и перезапустите Vite. Изменение корневого `.env` требует перезапуска FastAPI.
Повторный запуск уже настроенного проекта: запустите два сервера, без повторного
создания `.env` и окружения. Чтобы получить обновления после их публикации:

```powershell
git switch main
git pull --ff-only origin main
```

## Проверка приложения

1. На странице отображается доступность сервера. `/health` проверяет HTTP API,
   но не готовность модели или worker.
2. Отправьте один непустой `.mov` в пределах `MAX_UPLOAD_MB` (по умолчанию 100 МиБ).
   `VITE_MAX_UPLOAD_MB` задаёт подсказку frontend; backend проверяет лимит сам.
3. После `201` появится настоящий UUID и ожидание результата. Запросы
   `GET /api/v1/jobs/{job_id}` выполняются последовательно примерно раз в 1,5 секунды.
4. Пока AI не настроен, задача завершится `failed / JOB_TIMEOUT` после общего срока.
   Интерфейс покажет `error.message` и `error.code` без успешного вердикта.
5. При заполнении очереди появится сообщение о перегрузке; при неверном ключе —
   сообщение об отсутствии доступа. Ошибка не превращается в результат анализа.
6. После подключения модели `done` отобразит вердикт, события, таймкоды и JPEG/base64.
   Настоящие результаты модели и время анализа на этом этапе не проверялись.

Воспроизведение `.mov` зависит от кодека и браузера. Ошибка предпросмотра
не препятствует загрузке. Декодирование видео проверит AI/CV-обработчик.
История и кадры хранятся в памяти текущей вкладки; после перезагрузки история пуста.
Старые данные прежней версии из localStorage не используются. Серверная очистка
не может удалить ранее созданные браузерные копии.

## Проверки frontend

Из папки `frontend`:

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

`index.html` подключает `src/main.tsx`. Автоматического демо-анализа нет.
Примеры в `src/data` не подключены к рабочему экрану.
Отсутствующие confidence/source не заменяются выдуманными значениями;
нормативный источник текущий backend передаёт внутри `description`.

Изолированная проверка в headless Edge прошла через настоящие Vite/FastAPI и
временную SQLite: загрузка `201`, статус `processing`, перегрузка `503`,
`failed / JOB_TIMEOUT`, оба успешных вердикта, просмотр и скачивание JPEG.
Успешные ответы внесены в тестовую БД синтетически, без запуска AI-модели.
Проверено отсутствие API-ключа в браузерных запросах и сборке.
