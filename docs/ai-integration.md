# Контракт интеграции AI/CV и backend

Реальный обработчик модели в репозитории пока отсутствует. Backend не выбирает
вердикт без анализа. Команда предоставляет импортируемую синхронную функцию:

```python
from pathlib import Path
from app.schemas import AnalysisResult


def analyze_video(video_path: Path) -> AnalysisResult:
    # Прочитать локальное видео, выполнить локальные модели и сформировать результат.
    # Реализацию предоставляет AI/CV-команда.
    raise NotImplementedError
```

Этот фрагмент описывает сигнатуру, его не нужно подключать вместо реальной модели.
Функция может вернуть `AnalysisResult` или обычный `dict` с той же структурой.
Backend дополняет результат `job_id` и `status`. Сама функция не работает с HTTP,
API-ключом, реестром задач или состояниями `processing/done/failed`.

## Вход

`video_path` — абсолютный `pathlib.Path` к сохранённому `.mov`. Файл остаётся на
диске после выполнения до истечения срока хранения (по умолчанию 24 часа от
завершения задачи); перемещать или удалять его внутри обработчика не нужно.
Содержимое на этапе загрузки ещё не проверяется декодером: AI-адаптер должен
распознавать повреждённое видео и сообщать об ошибке исключением.

Обработчик вызывается в отдельном процессе через `spawn`, в том числе в Windows.
Инициализация моделей должна быть безопасна при импорте и не запускать второй
API/worker. Не запускайте обработку автоматически на уровне модуля.
Каждая задача сейчас получает новый процесс: импорт библиотек и загрузка весов
входят в таймаут. Веса должны быть подготовлены на локальном диске заранее.

## Результат без событий

```json
{"verdict": "no_violation", "violations": []}
```

Возвращать его можно только после успешного анализа. Ошибка декодирования,
отсутствующие веса или сбой модели должны приводить к исключению, а не этому вердикту.

## Результат с событиями

```json
{
  "verdict": "violation",
  "violations": [
    {
      "type": "Название визуально проверяемого события",
      "timecode_sec": 44.2,
      "description": "Наблюдаемое действие, основание для проверки и нормативный источник",
      "evidence_frames": [
        {"timestamp_sec": 44.2, "image_base64": "ПОЛНЫЕ_JPEG_БАЙТЫ_В_BASE64"}
      ]
    }
  ]
}
```

Значение `image_base64` здесь — поясняющая заглушка. Настоящий результат обязан
содержать base64 от полных JPEG-байтов, без префикса `data:image/jpeg;base64,`.

Проверки схемы backend:

- Вердикт строго `violation` или `no_violation`.
- `violation` требует непустого списка; `no_violation` — пустого.
- Для каждого события нужны непустые `type` и `description` и 1–3 кадра.
- Таймкоды — конечные неотрицательные числа в секундах от начала видео.
- Кадры проверяются на корректный base64 и начальные/конечные маркеры JPEG.
  Полная проверка декодирования JPEG и границ таймкодов появится с OpenCV.
- Неизвестные поля результата отклоняются: дополнительные confidence, bbox,
  rule и другие данные нужно предварительно согласовать и адаптировать.

Пока нормативный источник включается в `description`, чтобы сохранить форму
обязательного JSON жюри. Команда должна предоставить реальное название документа,
по возможности пункт и ссылку, обосновывающие выбранное визуальное правило.

В этой версии функция формирует и события, и кадры. Если AI-команда возвращает
только таймкоды, добавим локальный адаптер OpenCV, извлекающий JPEG перед возвратом
результата. Это не требует изменения публичного API.

## Ошибки и запуск

Исключение анализатора превращается в `failed / ANALYZER_ERROR`, нарушение схемы
— в `failed / INVALID_RESULT`. В API возвращается общее сообщение без текста
исключения и путей; подробности остаются в локальном выводе процесса.
Позже можно согласовать отдельные типы исключений для ошибок декодирования и моделей.

После появления настоящего модуля укажите в `.env`, например:

```dotenv
ANALYZER_CALLABLE=your_cv_package.pipeline:analyze_video
```

Во втором терминале из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m app.worker
```

Импорт, обработка и формирование результата ограничены `JOB_TIMEOUT_SECONDS`
(по умолчанию 240 секунд) и остатком общего срока `TOTAL_JOB_TIMEOUT_SECONDS`
(по умолчанию 300 секунд от поступления запроса загрузки в FastAPI).
Например, после 290 секунд ожидания на выполнение останется максимум 10 секунд.
По превышении эффективного лимита дочерний процесс завершается.
По умолчанию одновременно допускается 5 незавершённых задач и одна задача
в выполнении; настройки API и worker должны совпадать. Долгий импорт/загрузка
весов тоже расходуют бюджет, поэтому их стоимость нужно измерить заранее.
Проверить реальную скорость нужно на целевой машине до публичной сдачи.

Облачные AI API и передача им видео, кадров или описаний запрещены кейсом.
Обработка должна работать без интернета после подготовки весов и окружения.

Срок хранения результата задаётся `JOB_RETENTION_SECONDS`. После удаления
видео и записи задачи API возвращает `404`, включая отсутствие её кадров base64.
Очисткой управляет backend. Worker освобождает владение файлами после остановки
дочернего процесса; анализатору не нужно самостоятельно очищать папки приложения.
